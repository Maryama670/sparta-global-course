# Recipe Box

A small in-memory Recipe Box with 5 endpoint-shaped functions and acceptance tests. No web framework, no HTTP server — the "endpoints" are plain Python functions validated with pydantic and exercised directly from the tests.

## Requirements

- Python 3.10 or newer
- Dependencies in `requirements.txt`: `pytest`, `pydantic`, `ruff`, `mypy`

## Setup

```bash
# 1. Create and activate a virtual environment
python3 -m venv .venv
source .venv/bin/activate         # macOS / Linux
# .venv\Scripts\activate          # Windows PowerShell

# 2. Install dependencies
pip install -r requirements.txt
```

## Running the tests

From the project root:

```bash
pytest
```

Expected result: **24 passed** in under a second.

## The 5 endpoints

Each endpoint is a function in `src/routes.py` that returns a `(status_code, body)` tuple:

| Function                       | Purpose                    | Success | Failure       |
| ------------------------------ | -------------------------- | ------- | ------------- |
| `get_all_recipes()`            | Return every recipe        | `200`   | —             |
| `get_recipe(id)`               | Fetch one recipe by id     | `200`   | `404`         |
| `create_recipe(payload)`       | Add a new recipe           | `201`   | `400`         |
| `update_recipe(id, payload)`   | Update an existing recipe  | `200`   | `400`, `404`  |
| `remove_recipe(id)`            | Delete a recipe            | `204`   | `404`         |

### Payload contract

`create_recipe` and `update_recipe` expect a dict matching this pydantic model:

```python
class RecipeInput(BaseModel):
    name: str
    ingredients: list[str]
    instructions: str
    created_by: str
    rate: int
```

Anything that fails validation returns `400`. Extra fields (including a client-supplied `id`) are ignored. `id` and `creation_date` are generated by `create_recipe`; `update_recipe` preserves them.
